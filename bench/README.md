# bench: the benchmark tools

Bun scripts for the measuring stick: run a task's product in a throwaway worktree, grade it against a hidden oracle, replay a bug against a layer, run an arm headless. Tasks, oracles, bugs and results live in the data folder, never here. Set `HSTACK_BENCH_MACHINE` to the machine file (`<data>/machine.json`, `{ "forbid": { "paths": [...] } }`); its folder is the data folder.

## Task file (`<data>/env/<task>.json`)

| field | meaning |
|---|---|
| `name` | short id, `^[a-z0-9][a-z0-9_-]*$`; worktrees are `/tmp/hstack-bench/<name>-<label>` |
| `repo` | absolute path of the product repo; refused under a forbidden path |
| `db` | `null` or a database name matching `^bench_[a-z0-9_]+$` |
| `port`, `ready` | the app's port (must be free) and the URL that answers 2xx-4xx once it is up; `ready` is `null` exactly when `start` is |
| `setup[]`, `start`, `teardown[]` | shell commands (`sh -c`, cwd = worktree); `start` runs in its own process group and is killed after; `start: null` (with `ready: null`) means no host app: grade runs setup, the oracle and teardown, and `env up` refuses the task |
| `oracle` | the command that runs the oracle and writes JUnit at `BENCH_JUNIT` |
| `junit` | the JUnit path, relative to the worktree; grade and replay refuse an absolute path or one that leaves the worktree (the file is deleted before a run and goes with the worktree) |
| `layers` | `{ unit, int, e2e: <command> }` for replay; `{ review, audit, evaluator: { brief, tools?, allow? } }` for agent-replay |
| `testTitle` | regex whose first group is a test title, to find the tests added or changed from a fix on |
| `appFile` | optional: a file the setup needs (relative to the repo); `oracle validate` reads a base commit without it as one with no app (controller ruling of step 5) |
| `timeoutSec` | bounds the ready wait and every oracle or layer command (default 1800) |

## Environment of every command

`BENCH_DIR` (worktree), `BENCH_DB`, `BENCH_PORT`, `BENCH_URL` (`http://localhost:<port>`), `BENCH_JUNIT` (absolute); the oracle also gets `BENCH_ORACLE` (the oracle folder), a layer `BENCH_EXCLUDE` (a file with one excluded title per line, empty in a baseline run; bench decides what counts, so a layer should run every test: one that skips the titles makes its baseline serve one bug only, can break a later test that needs a skipped one, and shows the titles in `ps` when they ride in argv). A command that creates or drops a database asserts the `bench_` pattern on the name first.

## Contracts

- **JUnit**: one `<testcase>` per check; its `name` starts with the check id (`<sha7>-T<n> ...`). A case with `<failure>` or `<error>` fails, one with `<skipped>` is an error, a missing case is an error.
- **`PRECONDITION:`**: each check first asserts that its feature's page, form, field or endpoint exists, with a message that starts with `PRECONDITION:`. A failed case is `precondition` (feature missing) when a line of its message starts, after spaces and an optional `<Word>Error: ` (`Error: `, `AssertionError: `), with `PRECONDITION:`; otherwise it is `fail`.

`ext list` enumerates the external task candidates (prereg 4.2, rulings 2-8 of step 4). For each group of `groups.json` and each of its languages it searches the repos of the tier (REST `search/repositories`, tier 1 `stars >= repo.starsMin`, tier 2 `repo.tier2StarsMin..starsMin-1`, `pushed:>=repo.pushedFrom created:<repo.createdBefore`, pages of 100, at most 10; star ranges start doubling and a range whose `total_count` reaches 1000 is halved), drops a repo by `repoOut`, reads the root of each remaining repo with one level of folders and then the marker files whose text a marker tests (GraphQL, 50 repos a query, halved while GitHub refuses it), and for each repo with a stack (`stackOf`) reads every merged PR created in the window that links an issue (GraphQL search, the created range halved while `issueCount` reaches 1000; number, dates, author type, base branch, file counts and paths, commit count, merge commit, closing issues: never a title, body, comment, review or diff). Each PR is a row of `candidates-<tier>.tsv` (`stack tier rank key id repo stars pr_created merged_at issue issue_created static`, `static` the `staticOut` reason or `ok`, rows sorted by `key` within each stack, `rank` 1-based among the `ok` rows); every repo searched is a row of `repos-<tier>.tsv` (`language repo stars stack reason`, `stack` a group id or `none`, `reason` the `repoOut` reason, `unreachable` or `ok`). Every response is written to `raw/<sha256 of the JSON argv>.json` before it is parsed and a rerun reuses it, so a killed run resumes where it stopped (a search page with `incomplete_results`, or a saved answer that does not parse, is dropped and asked again). A stars range whose `total_count` is more than the repos collected from it is logged on stderr and summed as the stack's `slice shortfall` (the universe moves while it is read); a PR range that collects fewer PRs than its `issueCount` is an error naming the repo and the range, since the window is closed. A PR page that keeps failing with a 5xx or a broken connection is asked again with `first` halved (100, 50, 25, 12, 6) before the run gives up; a PR field GitHub left null keeps its total, so the PR falls out with a reason. A repo the tree batch cannot resolve is `unreachable` in `repos-<tier>.tsv`. REST searches go out 2.1 s apart; a rate limit waits for the reset (`gh api rate_limit`; 60 s for a secondary limit) up to 10 times, and a 5xx 15 s, twice (a GraphQL batch that times out answers 5xx and is then halved), each wait logged on stderr with the progress. stdout prints only counts per stack: repos searched, repos with markers, PRs read, `ok` rows, rows per reason, the slice shortfall, and the GraphQL points of every response the list used (saved ones too; stderr gives the points of new requests).

`ext check` checks one candidate of `candidates-<tier>.tsv` (the `ok` row of that stack and rank; rulings 9-11). `<key>` = `<owner>__<repo>`, `<slug>` = `<key>__<n>`, both lowercased with every character outside `a-z0-9_-` made `-`. It reads the PR's fields again (one GraphQL call: dates, merge commit, commit count, file paths, base branch, closing issues, the repo's licence and default branch; saved as `sealed/<slug>/pr.json`), fetches `git fetch --depth 2 origin <end>:refs/ext/<end>` into the bare `repos/<key>` (`git init --bare` and the `origin` remote once; the ref keeps the commit through a gc; 1800 s, and a transfer under 1 kB/s for 300 s is given up), takes the base by `baseOf`, and saves the issue as it stood at the PR's `createdAt` as `tasks/<slug>/issue.json` (`{ title, body, asOf, editHistory }`: a `UserContentEdit`'s `diff` is the whole body of that version, so the body is the newest version at or before `createdAt`, `none` when no edit came after, `recovered` when one did and the earlier version is there, `unverified` with the current body otherwise; `RenamedTitleEvent`s after `createdAt` are undone). The recipe (`recipes/<key>/recipe.json`: `{ platform, dockerfile, test, probe, briefSha }`) is the repo's saved one when it was written under the current brief (its `briefSha`, the SHA-256 of `briefs/recipe.md` at its round) and still builds and probes at this base, else written by recipe rounds (a saved recipe under another brief, or with no `briefSha`, is never built: the first round is offered it as the starting point, and with no round left the candidate is `recipe failed`): `sealed-agent env/<key>.json recipe-<slug>-<k> --at <base> --tools Read,Glob,Grep`, the prompt `briefs/recipe.md` plus, on a retry, the failed recipe and the last 200 lines of its build or probe log; 3 rounds for the repo's first task that needs them (the first slug in `rounds.tsv`, a recheck of it too) and 1 for each further task (`recipes/<key>/rounds.tsv`: `k slug result`, one row per round, written `replied` as soon as the reply exists and its result filled in after, so a check interrupted after a reply still counts that round; a round with no reply is an error and is not spent; a reply that does not parse, lacks `COPY . /work` or `WORKDIR /work`, or asks for `--network=host`, `--security=insecure` or an ssh or secret mount is a spent round, `bad reply`, and the next round is told why). A build is `docker build --platform` of the commit's files (`git archive`) plus `.bench.Dockerfile`, an empty `.bench.Dockerfile.dockerignore` (so the repo's `.dockerignore` does not apply) and `.bench-test.sh`, tagged `bench-ext/<slug>:<sha7>`, 45 minutes; a failed build is run once more (from the BuildKit cache), and when it fails again with a network signature in its last 200 log lines (`dial tcp`, `no such host`, `toomanyrequests`, `i/o timeout`, an HTTP 502 or 503 and the like) it is `error build`, `check.err` naming only the signature (a `failed to resolve source metadata` line that also says `not found`, `pull access denied` or `manifest unknown`, as for a `FROM` image or tag that does not exist, is the recipe's failure instead; `no space left on device` or `disk quota exceeded` there is `error build` too, naming only that signature, when the free-disk estimate taken then is below 15 GB or cannot be made: a full Docker disk is the machine's failure, a repo that prints it on a roomy disk is judged as usual); a run is `docker create --network none --name bench-ext-<slug>-<label> <image> sh /work/.bench-run.sh`, `docker cp` of `.bench-run.sh` and `.bench-test.sh` (and, at the base, the PR's test files from the end, the test files it deleted removed by `.bench-run.sh`), `docker start -a`, 30 minutes (then `docker kill` of that container), and `docker cp` of `/out/junit.xml` out (none is no case; `.bench-run.sh` first removes a `/out/junit.xml` the image may hold). A run that ends with exit 137 or 143 without our limit firing (killed from outside), or that exits non-zero with a disk signature in its log tail while the disk is low (as for a build), is `error run`; one our limit stopped is a finished run; one Docker reports `OOMKilled` is the repo not fitting the machine (ruling 10): its log ends with a line saying so, a probe's is a failed probe told to the next round, and a base or end run makes the candidate `out of memory` (the later runs are not made). `meta.json` `runs` records per run `{ label, timedOut, exitCode, cases }`, plus `oom: true` for a run killed for memory. Every git, gh and docker call has a limit (300 s unless named here), and a call that reaches it is an error of its stage. A probe runs the recipe's `probe` files plus one file of the base under the stack's test paths whose extension no probe file has (`extraProbe`: the first in path order; none, no extra file), so a test script that fails on a fixture or data file fails in a readable round, and passes with one passing case. The end image is built; then one run of the base image with the PR's tests and two of the end image give `failToPass`. When all three runs give no case and exit non-zero (`needsFeedback`), one more recipe round is run, even at a spent budget (`rounds.tsv` result `feedback <result>`), its prompt the brief plus only the fixed sentence `FEEDBACK`; a recipe that passes it is saved, the end image is rebuilt and the three runs are made again (labels with an `f`: `base-<n>f`, `end-<n>f-1`, `end-<n>f-2`, log `endf.build.log`); a feedback round that fails leaves the first runs' verdict. The sample of a stack is `sampleOf`: its first `perStack` accepted rows by tier and rank, at most `perRepo` per repo. `bun bench/ext.mjs sample <groups.json> [--tier <1|2>]` writes `<data>/ext/sample.tsv` (`task stack tier rank id url pr issue base end method f2p edit_history platform cold_setup`, `task` = `<stack>-<nn>`, stacks in id order, rows in task id order, `cold_setup` `yes` for the rows of the stack's `coldSetup` repo; a row keeps the `task` id of the live `sample.tsv`, else of `progress/step4/sample.tsv`, and a new row takes its stack's next number after the highest that sample or a `<data>/<stack>-<nn>/` folder holds (`keptIds`: a dropped task's id is never reused, ruling 2 of step 5)) from `walk.tsv`, the candidate lists and each task's `meta.json`. Note for ruling 14: `nextToCheck` counts every accepted row, while `sampleOf` also caps 2 per repo; they differ only if a recheck gives a repo a third accepted row, which then needs handling. Every test file path reaches `.bench-test.sh` as one single-quoted word (`word`), the same for the probe and the PR's runs. Logs of the base go to `recipes/<key>/rounds/`, everything after the PR's tests are in to `sealed/<slug>/logs/`; `sealed/<slug>/f2p.json` = `{ f2p, p2p }` case ids. `tasks/<slug>/meta.json` holds ids, dates, SHAs, counts and flags, and every container, image name and image id the check created (kept over attempts; base and end containers carry the attempt number). `meta.json` `recipeSha` is the SHA-256 of the recipe JSON the check used (`recipe.json` holds only the repo's latest). Before anything else, `check` makes the same disk-floor check as `walk` and, below it, prints `<stack> stopped: docker disk low (<n> GB free)` and exits 3. Verdict, appended to `walk.tsv` (`stack tier rank id result`) and printed as the only stdout line: `<slug> ok f2p=<n> p2p=<m>`, `<slug> out <reason>` (`rebase merge of several commits`, `recipe failed`, `end build failed`, `out of memory`, `PR tests do not pass at end`, `no fail-to-pass test`) or `<slug> error <stage>` (`fetch`, `clone`, `base`, `issue`, `recipe-agent`, `build`, `run`, `cp`: gh, git, the docker daemon or the network, a recipe agent with no reply, a run killed from outside, any throw of check itself), the tool's message in `tasks/<slug>/check.err`. A build that fails while `docker version` reaches the daemon is the repo's failure.

`ext walk` checks the stack's `ok` rows (with `--tier 2`, tier 1's then tier 2's) in the order `nextToCheck` gives, resuming from `walk.tsv` (the last row of an id counts; a row whose result starts with `error` or `recheck` (`recheck: <reason>`, appended by hand when a ruling reopens an out row) is checked again), writing the rows it passes over as `repo cap`, and stops at `perStack` accepted, at the end of the list or after 2 errors in a row; it prints each check's line, then `<stack> tier <n>: accepted <a>, checked <c>, list end <yes|no>`, with `, stopped on 2 errors in a row` and exit 4 when that stopped it. Before each check it estimates Docker's free disk without a container (Docker Desktop's `DiskSizeMiB` from `~/Library/Group Containers/group.com.docker/settings-store.json`, else the apparent size of the VM's `Docker.raw`, 90% of it usable, minus the sizes `docker system df` prints); below 15 GB it prints `<stack> stopped: docker disk low (<n> GB free)` and exits 3; an estimate it cannot make is said once on stderr and the walk goes on. `--remove-out`, after an `out` or `ok` verdict (an accepted task keeps its recipe and, in `meta.json` `imageDigests`, `{ <image name>: <docker image inspect .Id> }`, not its images; step 5 rebuilds; an image with no digest is kept and named on stderr), runs `docker rm` on each container and `docker rmi` on each image name that candidate's `meta.json` records (never `-f`; only names starting `bench-ext-<slug>-` or `bench-ext/<slug>:`), and `docker rmi` on a recorded image id that no tag points at any more, appending each name removed to `removed.txt`.

`ext task-env` writes a step 5 external task's files (rulings 3 and 4 of step 5). The task id resolves through the live `ext/sample.tsv` (else `progress/step4/sample.tsv`) to its PR id, `<key>` and `<slug>`. The recipe, `tasks/<slug>/task-recipe.json` (`{ platform, dockerfile, test, probe }`), is parsed by `parseRecipe` from `--reply`, the reply file the step 4 lock names, whose SHA-256 (of its bytes) must equal `--sha` (else exit 2, nothing written), or, with `--from-meta` (a replacement), from the first `recipes/<key>/rounds/<k>.reply.md` whose parsed recipe hashes (`JSON.stringify`) to `meta.json` `recipeSha`. `<data>/<task>/input.md` is `# <title>`, a blank line and the body of `tasks/<slug>/issue.json`, verbatim; `bench/input-check.mjs` runs on it and stdout is only `<task> input-check hits=<n>` (recorded, not enforced). `<data>/env/<task>.json` is `{ name: <task>, repo: <data>/ext/repos/<key>, db: null, port: 49152 + <the task's 0-based row in that sample.tsv>, start: null, ready: null, setup: [], teardown: [], oracle: "bun <absolute bench>/ext.mjs oracle-run <task>", junit: ".bench-junit.xml", timeoutSec: 7800 }`; the port is never bound (no host app), and the oracle path is the checkout `task-env` ran from.

`ext serve` checks that a task's app can be served offline (ruling 5 of step 5). A stack outside `ext/step5.json` `serveRequired` gets `serve/<key>/serve.json` = `{ layer: [], start: "", ready: "true", notes: "", briefSha: null }` with no round and no Docker (`<task> servable rounds=0`). Otherwise, after the disk-floor check (below the floor it runs `docker builder prune -f` and estimates again; still below, `<task> stopped: docker disk low (<n> GB free)`, exit 3), a serve recipe (`{ layer, start, ready, notes }`; `parseServe`, the same Dockerfile hazards as a recipe refused in `layer`, and an empty `start` refused: an empty recipe would pass with nothing served) is tried at the task's base and then at its end: the image `bench-ext/<slug>:<sha7>-serve` is built as `check` builds (the task recipe's Dockerfile plus the `layer` lines; 45 minutes, the same retry, network and disk signatures), and one container `bench-ext-<slug>-serve-<sha7>-<n>` (`docker create --network none`, static command `sh /work/.bench-serve.sh`, `.bench-serve.sh`, `.bench-start.sh` and `.bench-ready.sh` in by `docker cp`) runs `start` in the background and `ready` every 2 s until it exits 0 (`bench: ready`, exit 0) or 600 s pass by the clock (a background `sleep 600` then touches `/tmp/.bench-ready-limit`; a `ready` that answers only after it fails; exit 3, after one more `ready` run whose output the log keeps); `docker start -a` is bounded at 900 s (then `docker kill`). The saved `serve/<key>/serve.json` is tried first when its `briefSha` is the SHA-256 of the current `briefs/serve.md` (not a round; labels `reuse-<slug>-<n>`); else, or when it fails, serve rounds as recipe rounds: `sealed-agent env/<key>.json serve-<slug>-<k> --at <base> --tools Read,Glob,Grep`, the prompt `briefs/serve.md` plus, on a retry, the previous recipe and the last 200 lines of its base build or serve log (`build failed`, `serve failed`), only that it served at the base and not at the later commit (`end failed`), or why the reply did not parse (`bad reply`); 3 rounds for the repo's first task that needs them, 1 for each further task (`serve/<key>/rounds.tsv`, `k slug result`, written `replied` as soon as the reply exists; a round with no reply is `error serve-agent` and not spent). A passing round's recipe is saved with `briefSha`. A run Docker reports `OOMKilled` ends the rounds. Verdict, the only stdout line: `<task> servable rounds=<this slug's rows in rounds.tsv>`, `<task> dropped not servable`, `<task> dropped out of memory` (both append `dropped` for the task's PR id to `walk.tsv`, exit 0), or `<task> error <stage>` (`prune` (the builder prune failed), `task-env` (no `task-recipe.json`), `reuse` (a saved `serve.json` that does not parse), `serve-agent`, `build`, `run`, `cp`; the message in `tasks/<slug>/serve.err`, exit 1). Base logs go to `serve/<key>/rounds/<label>.base{.build,}.log`, end logs to `sealed/<slug>/logs/serve-<label>.end{.build,}.log`. Each image and container is appended to `<data>/<task>/docker.json` (`{ images: [{ name, id }], containers: [name], digests }`) when it is created, and when the check ends (in every outcome) `removeRecorded` removes them: each image name still present first gets its digest (`docker image inspect .Id`) in `digests`, then `docker rm` of each container and `docker rmi` of each image name it records (never `-f`; only names starting `bench-ext-<slug>-` or `bench-ext/<slug>:`; one already gone is passed over) and of each recorded id no tag points at any more, appending each name removed to `ext/removed.txt` (the user's decision of 2026-11-03; `--remove-out` shares the same removal, which `docker kill`s each recorded container before its `docker rm`, an error when it is not running).

`ext oracle-run` is the `oracle` command `task-env` writes into an external task's task file (`start: null`), so `grade` runs it in its worktree of the commit with `BENCH_DIR`, `BENCH_ORACLE` and `BENCH_JUNIT` (step 5). It first reads and checks `<oracle>/runner.json` (`{ layer: [Dockerfile lines], run: <sh body> }`, the same Dockerfile hazards as a recipe refused in `layer`, `run` not empty), `tasks/<slug>/task-recipe.json` and `serve/<key>/serve.json` (`briefSha` `null`: the empty serve recipe of a stack with no serve check); any of them absent or malformed is an error before any Docker call, so grade records no JUnit for that commit. It also reads `tasks/<slug>/rebuild.json` when it exists (`{ lines: [shell lines] }`) and works out the rebuild lines (`rebuildLines`, step 11 ruling 4): the recipe must copy the repo into /work exactly once (`COPY . /work` or `COPY ./ /work`, flags allowed, counted over the whole Dockerfile; otherwise `the recipe must copy the repo into /work exactly once`), and then either `rebuild.json`'s lines, run in `/work`, or the recipe's instructions after that copy and then the serve `layer`'s, as shell lines (a `\` continuation joined, blank and comment lines inside it skipped, as Docker does): `cd /` and the final stage's `ARG` and `WORKDIR` lines before the copy first, then `RUN` under the final stage's last `SHELL` before the copy (JSON form; one that is not a JSON array is refused) or else `sh -c` (exec form as its quoted words, a cache or tmpfs mount dropped), `ENV` and `ARG` exported, `WORKDIR` made and entered, `CMD`, `ENTRYPOINT`, `EXPOSE`, `HEALTHCHECK`, `LABEL`, `MAINTAINER` and `STOPSIGNAL` passed over (the image keeps R's config); any other instruction (`COPY`, `ADD`, `USER`, `SHELL`, `VOLUME`, `FROM`, ...), a heredoc or another mount is refused, naming `rebuild.json`. All of this is an error before any Docker call. With `BENCH_TRUSTED=1` (`grade --trusted`) it first refuses, also before any Docker call, a HEAD that is no task's base or end (live `ext/sample.tsv`, `<data>/tasks.json`; each resolved with `git rev-parse --verify <sha>^{commit}` in `BENCH_DIR` and compared whole, so a short sha's prefix never matches another commit) and that no `refs/seeded/*` ref points at: `oracle-run --trusted: <sha7> is no task's base or end and no seeded bug`. Then the disk floor as `serve` checks it (`docker builder prune -f` once, then an error when still below). `<osha8>` is the first 8 hex of the oracle folder's `oracleSha`, as grade counts it.

The private task set (step 11 rulings 8 and 9) has the shape of an external task. A task that is not in `ext/sample.tsv` but is a key of `<data>/tasks.json` resolves through `taskOf` to `{ task, slug, key, stack, base, end, index }` with `slug` = `key` = `real-estate` and `stack` = `re` (the constant `PRIVATE_SET` of `ext.mjs`; `bench/` takes the store key and stack name from it and nowhere else), `index` = 1000 + the task's position in `tasks.json` (so a port never collides with an external one), and `base`/`end` as `tasks.json` holds them, resolved to full shas with `git rev-parse --verify <sha>^{commit}` in the store `ext/repos/real-estate` when that folder exists (a sha the store lacks is an error), else kept as given. The rows carry no `tier`, `rank`, `cold_setup`, `f2p` or `pr`; no caller of `taskOf` reads them (`cold_setup` is read from `sample.tsv` directly). `ext/serve/<key>/serve.json` and a serve reply may carry an optional `services` string, the part of `start` the box also needs (absent: no field; not a string: refused).

`ext box-env <task>` writes `<data>/env/box/<task>.json` for an external or a private-set task, from this checkout: `{ name, repo: <data>/ext/repos/<key>, db: null, port: 49152 + index, start: null, ready: null, setup: [], teardown: [], oracle: <oracle-run command with this checkout's path>, junit: '.bench-junit.xml', timeoutSec: 7800 }`, plus `runner: <data>/env/real-estate/runner.json` for a private-set task. It writes only that file (never `env/<task>.json`, `env/seeded/*.json` or `env/canary/*.json`, which stay as the locks hashed them). `oracle-run` reads `runner.json` from the oracle folder and, when that folder has none, from the file the task file's `runner` names; `grade` passes the task file's path as `BENCH_TASK_FILE`, used only for this lookup. A runner in neither place is an error. The runner held outside the oracle folder is not part of `oracleSha`: a grade's `--reuse` key does not cover an external runner, so a changed runner needs a grade without `--reuse`.

The default path (step 11 ruling 4: a product gets no more network than its arm had). From the BuildKit cache on every grade: `S` = `bench-ext/<slug>:<base7>-serve` from `git archive <task base>` with the recipe plus the serve `layer` (with network, as `check` builds: 45 minutes, the same retry, network and disk signatures; its log is the base's, so readable: `<data>/<task>/build/<base7>-<m>.serve.build.log`, `<m>` one more than the recorded `<base7>-serve` entries, as the box counts them), and `R` = `bench-ext/<slug>:<base7>-runner-<osha8>`, `FROM S` plus the runner's `layer` from an empty context (log sealed: `grade-<sha7>-<n>.runner.build.log`). `productImage` then makes `bench-ext/<slug>:<sha7>-product-<osha8>` in a container `bench-ext-<slug>-make-<sha7>-<n>` from `R` (`docker create --network none ... sleep`; for `{ ips, hosts }`, a task whose arms reach pinned registry addresses, Docker's default bridge with the box's capability drops and `--add-host` pins, and the box's firewall helper allowing TCP 443 to those addresses, set from outside before any product line runs): `docker cp` puts `git ls-tree -r -z --name-only <base>` (NUL-separated, so a path with a space or a newline stays whole), the make script and the commit's export (`/tmp/bench-product`) in; `docker exec` runs, as the image's user, `overlayScript` (every base path removed from `/work` with `xargs -0 rm -rf`, so a file the product deleted is gone and an untracked build output such as `node_modules`, `target` or `.venv` stays; the export copied in with `cp -a`) and then the rebuild lines under `set -e`, bounded at 45 minutes, its output in the sealed `grade-<sha7>-<n>.make.log`; the container is committed (its `Cmd` is then the `sleep`, which no grade uses: every container passes its own command) and removed by name at once. A make that exits non-zero or passes its limit gives no image: oracle-run exits non-zero with no JUnit and no readiness line, so grade records no result (the product's `noresult`, as a build that fails in the box; install lines that need the network fail here and `rebuild.json` is how a task is rebuilt offline). The grade mode (`gradeMode(ext, t)`, step 11 ruling 5, M3) is `shared` when the serve recipe has no `start` (the empty serve recipe: the checks call the code inside the runner's own process, so M3 stays open there) or `ext/tasks/<slug>/grade-mode` (trimmed) reads `shared` (set only from a served task's end regrade, never from a product), else `split`. In `shared` mode one container `bench-ext-<slug>-grade-<sha7>-<n>` from the product image runs the grade, as below. In `split` mode both names are recorded first, `P` before `O`, so removal kills `P` first: `P` = `bench-ext-<slug>-app-<sha7>-<n>` from the product image, `--network none`, runs only `start` (passed as an argument to `sh -c`, so nothing is copied into `P`: it has no `/oracle`) in the background in `/work` under a foreground `sleep <limit + 600>`, which keeps its network namespace up whether the app runs or dies and ends `P` by itself if oracle-run is killed; `O` = `bench-ext-<slug>-grade-<sha7>-<n>` from `R` (the base's files, none of the product's), created with `--network container:<P>` (it joins `P`'s namespace, so it reaches the app on `P`'s loopback and nothing else, and no network object is made), runs the grade below with no `start` of its own: `ready` runs in `O` against the shared loopback. The JUnit and the readiness markers are copied out of `O` only; nothing `P` writes (its own `/out` included) is read. After `O` ends, `docker logs <P>` is appended to the sealed grade log under `bench: the app's output (<P>):`, and `P` reported `OOMKilled` reads `memory` as `O`'s does. If `P` dies before `O` starts, `O` cannot join it: a Docker error, no JUnit, no readiness line. `<n>` is one more than the recorded `<sha7>-serve` and `<sha7>-product-*` entries of that commit (each recorded before it is made, so a run that failed on the way keeps its number and no log is overwritten).

The trusted path (`BENCH_TRUSTED=1`) builds HEAD itself as step 10 did: `bench-ext/<slug>:<sha7>-serve` from `git archive HEAD` of `BENCH_DIR` with the recipe plus the serve `layer`, with network (log `<data>/<task>/build/<sha7>-<m>.serve.build.log` when HEAD is the task's base and `sealed/<slug>/logs/grade-<sha7>-<n>.serve.build.log` at any other commit), then `bench-ext/<slug>:<sha7>-grade`, `FROM` it plus the runner's `layer` (log `grade-<sha7>-<n>.grade.build.log`), and the grade container from that image. It is for a trusted end that needs a dependency its base lacks (ruling 4); an arm's product never takes it.

The grade container (`docker create --network none`, static command `sh /oracle/.bench-grade.sh`) gets the oracle folder (without `node_modules`, symlinks copied as their own text, as `oracleSha` counts it) and `.bench-grade.sh`, `.bench-body.sh`, `.bench-start.sh`, `.bench-ready.sh`, `.bench-run.sh` in `/oracle` by `docker cp`; the script writes an empty JUnit `<testsuites/>` to `/out/junit.xml` first (a run that never gets ready still has results: every check reads `error`, which grade's `verdict` calls `broken`; `oracle validate` reads it from `readiness.tsv` as not judged), then runs the body under the container's own 30-minute limit (a background timer touches `/out/.bench-timeout`, prints `bench: not done in <n> s, killed` and kills the process group, so the container exits 124 even when oracle-run itself was killed); the body runs serve's script from `/oracle` (`start` in the background in `/work`, `ready` every 2 s until it exits 0 or 600 s pass by the clock), and once ready touches `/out/.bench-ready` and runs `run` in `/work`, which rewrites `/out/junit.xml`. `docker start -a` is also bounded at 30 minutes on the host (then `docker kill` of that container); `/out` is copied out and `/out/junit.xml` goes to `BENCH_JUNIT`. The one readable line per run that reaches its end is `<sha7>\t<osha8>\t<ready|not ready|timeout|memory>` appended to `<data>/<task>/build/readiness.tsv` (step 11 ruling 7: every reader, `readinessOf(file, sha7, osha8)`, takes the last line of its own commit and oracle; a step 10 two-column line names no oracle and is never read); a run either limit stopped (the host's, or `/out/.bench-timeout`) writes no JUnit and exits non-zero, as does one Docker reports `OOMKilled` (its readiness line still written). Everything else the container prints goes to `sealed/<slug>/logs/grade-<sha7>-<n>.log` and then to oracle-run's stderr, so grade the external tasks only with `--sealed`. Each name is recorded in `<data>/<task>/docker.json` as it is created (an image name before its build, its id after), and when the run ends, in every outcome, `removeRecorded` removes them as `serve` does (the user's decision of 2026-11-03: digests kept). On SIGTERM or SIGINT it `docker kill`s the containers it created, removes what it recorded and exits 143. grade kills its oracle command's group with SIGKILL at `timeoutSec` (7800 s), which no handler sees; the builds, the make and the run (each build and the make 2700 s, the run 1800 s; S and R normally come from the cache in seconds) normally end first under their own limits, but builds that miss the cache, a build's retry (a second 2700 s) or a prune (1800 s) can pass it, and `bun bench/ext.mjs remove <task>` removes what such a run left (`removeRecorded` for that task, its containers `docker kill`ed first, since a killed oracle-run leaves its container running; prints `<task> removed <n>`). The image holds the commit (`git archive HEAD`), never uncommitted changes of `BENCH_DIR`.

`sealed-agent` runs one `claude -p` with the prompt file's text and the listed tools (none by default), in an empty folder or the files of `--at` with no `.git` and no `.claude/settings.json`, and the agent env (no `BENCH_*`, `PG*`, `HSTACK_BENCH_MACHINE`, `DATABASE_URL` or `PAYLOAD_DROP_DATABASE`; `DOCKER_HOST=unix:///nonexistent`), with `--no-session-persistence` (`noPersist`) so no transcript is kept under `~/.claude/projects`, and with `--settings <file>` the file's absolute path as `claude --settings` (permission rules, `additionalDirectories`; a missing file is refused), and with `--model <id>` that model as `claude --model`; it writes the reply to `--out` and `<out>.run.json` (`label`, `at`, `model` (the requested id or `null`), `settings` (absolute path or `null`), `start`, `end`, `code`, `version`, `tools`, `usage`, `models`, `toolUses` (tool calls by tool name), and the fields a caller's `record(stream)` option returns), refuses an existing `--out` or run record, and on no result or a non-zero exit writes only the run record and exits 1.

`grade --at` prints `<sha7> junit=<ok|missing|timeout> pass=… excluded=… build=…` and exits non-zero when the JUnit is not ok (the grade file is still written). It reads every `validation-*.json` next to the oracle folder and leaves out of the score each check whose verdict there is `weak`, `broken`, `pre-existing` or `error` (spec 7.1; `unscored`); the grade file lists them as `excluded: [{ id, verdict }]` and keeps their per-check result. Every grade file records `oracleSha`, the SHA-256 of the oracle folder (every file, paths relative to it, without `node_modules`).

`--sealed`: the oracle command's stdout and stderr go to `<task dir>/logs/<sha7>-<n>.log` (`<task dir>` holds the oracle folder, `<n>` the next free number), never to the terminal; setup and teardown output go nowhere and the app's start log (`<worktree>.log` in the temp folder) is removed when the run ends, so a start that fails has no log: rerun without `--sealed` on a commit that holds no bug to see why. stdout carries only the counts lines and, with `--validate`, the verdict line. `--reuse`: a commit whose `grades/<sha7>.json` records the same commit, the same `oracleSha` and `junit` `ok` is not run again; its results are taken, the grade file is rewritten with the current exclusions and the counts line ends in `reused`. grade's default is unsealed, so the step 7 and 8 drivers must pass `--sealed`.

`--validate` runs the oracle on the ref, on every known-bad version (`--bad`, more than once: the fix's parent and the task's end product; the old `--validate <ref> <bad>` form still works) and on the base. Verdicts, in this order: `broken` (ref not pass), `weak` (passes on any bad), `broken` (any bad neither pass nor fail), `pre-existing` (base fails), `absent-at-base` (base precondition), `broken` (base error: the base run gave no result), `valid` (base passes, or no base). With no `--base` (the external form, ruling 10 of step 5: the known-bad version is the base), a check whose bads are all `fail` or `precondition` with at least one `precondition` is `absent-at-base` instead of `broken`; with `--base` a precondition on a bad stays `broken`. Sealed mode prints only `<id> caught|missed|error`. `bug.json` is `{ id, at, patch, fix }`, `patch` relative to it and in the fix's direction (replay applies it with `-R`); agent-replay adds `task` (the task that introduced the bug) and, for review and audit, that task's `base` and `end` (and needs `fix`: a bug whose fix is already in `end` is refused, since the end product holds the fix). agent-replay and run-arm refuse a run whose record in `results/` exists. The review layer's agent works in a folder that holds one file, `task.diff` (`git diff <base> <end>`), and its prompt names the file instead of carrying the diff, so a task diff over 1 MB still starts. Every agent on the host (replay, judge, sealed) gets `agentEnv()`: no `BENCH_*`, `PG*`, `HSTACK_BENCH_MACHINE`, `DATABASE_URL` or `PAYLOAD_DROP_DATABASE`, and `DOCKER_HOST=unix:///nonexistent`, so its docker CLI reaches no daemon (the inputs of p1-p6c say `docker compose down -v`); setup and teardown run with the bench env. agent-replay's layer and judge calls and sealed-agent pass `noPersist` (`--no-session-persistence`); run-arm's turns do not, since it resumes its session in the box.

`run-arm` runs an arm only in its box (`box.mjs`; `runArm(args, { root, box = enterBox })`, no host path): the task's serve image plus the arm layer, nothing mounted, the firewall set from outside, the CLI from `arms.json` `cli` (a regular file, relative to `arms.json`: `{ model?, smallModel, cli, plugins: { H: [], W: [] }, turnTimeoutSec? }`). A probe turn checks what loaded (a probe whose exit is not 0 is refused: exit 2, no record); then the prompt `input.md`, a blank line, `interface.md` beside it (a missing sheet is refused before any call) and the DONE line, up to 5 resumes. The box takes no plugin dir yet (`H`, `W`: the plan of step 11) and refuses one before any Docker call. The product comes back only as a git bundle of the box's HEAD, written into the run folder, fetched into the task repo as `bench/<task>-<arm>-<n>` with `-c gc.auto=0` (a gc would prune what a repo on its alternates borrows) and deleted; the folder and its `.git` never come back. An arm record (`results/<task>-<arm>-<n>.json`) holds the CLI `version` from the init event, `box` (image id, memory cap, the allowed addresses and routes), `envCommit` (the box's `env` commit, so `git diff <envCommit> <product>` leaves build outputs out), `toolUses` (tool calls by name, over the main and resume turns) and `machine: null|'api'|'model'|'killed'|'memory'|'product'` and `fallback` (`{ original, fallback, category }` from the first model-fallback notice of the probe or a turn, else `null`). A `machine` run is the machine's failure and never the arm's weakness (ruling 11): `api` (a main or resume turn ended with `is_error`), `model` (a main or resume turn holds a `model_fallback` or `model_refusal_fallback` notice, which moves the whole session to another model even though `modelUsage` still lists the arm's; or the arm has a configured model and the turns served others; a subagent's other model is fine), `killed` (the host killed the box, or it restarted or died), `memory` (the kernel killed the CLI before the limit), `product` (the bundle or the fetch failed). It stops at once, gets no product step and no branch, keeps its record (`status: abandoned`, `reason: machine`) and exits 3. A turn that outlives `turnTimeoutSec` is the arm's own `timeout`: `reason: timeout`, the interventions, and its product is still saved. An arm that reads the data folder or the task repo finds neither: they are not in the box.

`canary` drives step 8's canary (B and B- on the first 2 tasks of each stack in `ext/sample.tsv`, k = 2 standing runs per arm; a run stands when its record has `machine: null` and the arm's model now in `arms.json`). `bun bench/canary.mjs run <task>` goes in `queuePick` order (seed from `ext/groups.json`), each product graded right after its run with `grade --at <sha> --sealed`, resuming from `results/` and `grades/`: it repeats neither a finished run nor a finished grade. The next run number is the highest of any record plus one, so a `machine` run takes its slot's place under a new number and a rerun on a weaker `smallModel` leaves the older B- runs out. A grade is good when `grades/<sha7>.json` has the commit and `junit` ok and the last `build/readiness.tsv` line of that sha7 and the grade file's oracle (`oracleSha`) reads `ready`, and at least one of its checks is not `error` (a runner that dies after ready leaves a placeholder JUnit of all `error`); one that is not good is run once more (`canary/attempts.json` counts the attempts per sha) and the second stands, with every check `error` reading 0. Every grade of the canary (`run` and `diagnose`) uses `env/canary/<task>.json`, the task file with only `oracle` changed to this checkout's `ext.mjs oracle-run`, run as `cd <this checkout's bench folder> && bun --no-env-file <ext.mjs> oracle-run <task>` so that the product's own runtime config and env file never take effect on the host (`task-env` writes the same command in new `env/<task>.json` files; existing ones are not rewritten) (the original names the main checkout's, which would grade a product without this branch's guards; the original is hashed in the locks and stays; `run-arm` keeps using it), written when missing or different. A grade the machine spoiled (`docker version` fails, or the disk is under its floor) counts no attempt. Before a task the build cache is read from `docker system df` and `docker builder prune -f` runs above 15 GB. It prints `grade`'s count lines and `<task> <arm> <n> <status> grade=<ok|again|noresult>` (a memory kill reads as `noresult` under `--sealed`; a `machine memory` run is printed). Exit 3 on a stop, with `<task> stopped: <refused|api|machine>`. A machine failure on the probe is exit 2 with no record, and the driver stops. `bun bench/canary.mjs report` writes `canary/report.json` and prints per task `b`, `bMinus`, `d`, `dBuild`, `dRequirement`, B's spread of score, tokens and minutes, and per run tokens (input + output, cache reads apart), minutes, status, `machine`, B-'s `toolUses`, then `canary mean=<m> favour=<n>/6 verdict=<pass|fail|not judged>`; `not judged` while any run has no score. After those lines `report` prints the per-task lines of the extended canary's tasks that have runs (the kept `cold_setup` `no` tasks of `ext/sample.tsv` that are not the 6, from `extendedTasks`), then `extended mean=<m> lower=<l> upper=<u> t_lower=<t> t_upper=<t> favour=<n>/<tasks> verdict=<pass|fail|not judged>` (bounds to 6 decimals; the lower bound of a 95% bootstrap interval of the mean of d over those tasks, seed `hstack-bench-2026-10-27`, must be > 0; `not judged` until each has 2 scored runs per arm) and `all20 mean=<m> lower=<l> favour=<n>/<tasks> judged=<yes|no>` (over the 6 and the extended tasks together, deciding nothing); `report.json` gains `extended` and `all20`, and `diagnose` still reads only the original verdict. `bun bench/canary.mjs diagnose` refuses unless the last report's verdict is `fail`; it grades the standing B- products with the seeded oracle (`--sealed`), prints per product the pass, fail, precondition and error counts of the non-excluded checks, and writes `git diff <envCommit> <product>` (no external diff, no textconv) of one B and one B- product of the 3 tasks with the lowest `d` to `canary/pairs/<task>-<arm>.diff`.

`trial` drives step 11's trial (ruling 12): arms H and B, k = 1, on the tasks named one per line in `<data>/trial/tasks.txt`. `bun bench/trial.mjs run <task>` refuses a task not in that file, a task whose `cold_setup` is `yes` in `ext/sample.tsv`, a task listed in `<data>/step11/walked.txt` (whether or not it has a sample.tsv row), and a task whose `step.json` has no ids (`no step id`); it needs `env/box/<task>.json` and `<task>/step.json`. The first `run` of a task writes `trial/floor.json` `{ <task>: { H, B } }` (the highest run number of any record of that arm then, 0 if none; never overwritten): `run` and `report` count only records above it, so the canary's `<task>-B-<n>` runs and grades are never taken, regraded or removed, and the first trial B takes the next number. `report` applies the same gates to every line of tasks.txt (the no-step-id case prints `trial not judged: <task>: no step id`); CR line ends in tasks.txt and sample.tsv are ignored. It is the canary's loop (`runTask`, `gradeProduct` and the attempt rule, exported from `canary.mjs`) with the slots `B:1` and `H:1` in `queuePick` order, the arms run and the shas read from `env/box/<task>.json`, each product graded right after its run with `--sealed` against `<task>/oracle` and, when `step.json` names `step/oracle` with ids (the real-estate shape), also `<task>/step/oracle` (grades in `step/grades/`), the attempts in `trial/attempts.json` (a key `step/grades:<sha>` for the step oracle), and the same resume, `machine` and stop (exit 3) rules as the canary. `bun bench/trial.mjs report` writes `trial/report.json` and prints per task and arm `<task> <arm> build= requirement= passed= tokens= cache= minutes= interventions= end=` (build and requirement per step 6 ruling 7 through `scoreAt`; tokens input + output; `cache` cache read, `cacheWrite` is in the json; `end` the record's reason, else its status, spaces as `_`; no check id or per-check result), then `trial sigma_d=<s> sigma_d_ext=<s> n=<tasks> N=<N> h1_n=<k> walk=<yes|no>`: `sigma_d` the sample standard deviation (n - 1) of `build(H) - build(B)` over the tasks (a null build counts 0 in both arms), `sigma_d_ext` the same over the tasks that have a row in `ext/sample.tsv` (decides nothing), `N` = 24 when sigma_d <= 0.25, else `max(24, pairedTasks(sigma_d, 0.15) + 2)`, `h1_n` the rows of `ext/sample.tsv` whose `step.json` has ids, `walk=yes` when `h1_n < N`. While any run has no final score the line is `trial not judged`. Exports `sigmaD` and `nRule`.

`replay` first checks that the patch reverse-applies (`git apply -R --check` in a throwaway worktree at `at`); one that does not is an error (exit 2, sealed: `<id> patch does not apply`) before any baseline is read or run. It then runs the layer at `at` without the bug: the baseline, kept as `<data>/results/baseline-<task>-<at7>-<layer>.xml` and reused by every bug at that task, commit and layer (delete it to rerun; a baseline with no results or no non-skip case is `<id> error` and is not kept). It then runs the layer with the patch reverse-applied. Excluded titles are the tests added or changed in test files from the fix's parent to `at` (`git diff <fix>^ <at>`, files read at `at`; spec 8.1: the failing assertion must have existed before the fix); a title with no literal text (only `%s`, `$name`, `${x}`) would match every case and is dropped (dev mode says so on stderr). A catch is a failing case that is neither excluded nor failing in the baseline, matched by name. Dev mode prints each failing case as `FAIL <name>`, marked `(excluded)` or `(fails at baseline)` when it does not count, and the baseline file and its failing count on stderr; sealed mode is quiet in both runs. `fix` must not be a merge commit.

`bugs` reads every `<folder>/*.json` except `*.run.json`, `done.json` and `<name>-done.json` as a bug file: `{ id, fix, at, patch, description, hunks: [{ file, old }], kind?, severity?, source?, dropped? }`, `old` the start of the hunk's old side in `git diff -U0 --no-renames <fix>^ <fix>` (a pure addition gives the line it follows), `dropped` a reason. Without `--usable` it checks each bug and writes into its file `task` (the owner, `null` with none), `base` and `end` (from `tasks.json`, only with an owner) and `out`, the first that holds of `"dropped"`, `"patch does not apply"` (`git apply -R --check` at `at`, in a throwaway `check-<id>` worktree), `"fix is a merge commit"`, `"no owner"`, `"fix in end"` (`git merge-base --is-ancestor <fix> <end>`), else `null`. The owner is the task with the most `task_lines` in `<data>/tasks/<task>.tsv` over the rows that match a hunk (`commit` = the fix's 7-char sha, same `file`, `old_lines` starting at `old`), a tie going to the earlier task in `tasks.json`; with no such row, the first task whose range (`git rev-list --first-parent <base>..<end>`) holds the fix. Usable: unit, int and e2e take `out` `null`, `"no owner"` or `"fix in end"`; the evaluator `null` or `"fix in end"`; review and audit `null`. `--usable <layer>` prints the usable bug file paths, one per line; it reads only the written `out` (a file without one is an error: run the check first), runs no git and writes nothing, so batches running at once can all call it. `--fix-tally <sha,...>` (each `^[0-9a-f]{7,40}$`, else refused) prints, per listed sha only, `<sha> <n>`: the number of bug files whose `fix` starts with it; no git, no write, and no other sha or value is printed; a count still tells whether a listed sha is a held-out fix, so a list of every commit would name them all: on a sealed folder, run it only on the registered list (the 6 catalog shas and the dev shas, prereg §8.2). `--at-tally` prints only `at: 69ebe27 <n>, other <m>`: the number of bug files whose `at` is `69ebe27` (the base every bug file names) and of all the others (another value, none, or a file that does not parse); no git, no write, so it is safe on a sealed folder. Dev mode prints `<id> task=<task|none> out=<out|ok>` per bug, then the totals; sealed mode prints only the totals: bugs, by `source`, `kind`, `severity`, owner task and `out`, the dropped bugs by `source`, usable per layer, the ids whose `out` is `patch does not apply` or `fix is a merge commit`, `finished: <value>` from `<folder>/done.json` (that field only), `<name>-done: considered <n>, finished <value>` per `<name>-done.json` (a sealed agent's progress note; the name printed only when it is 1-16 of `a-z0-9`, else `other-done`) and `usage <input>/<output>/<cacheRead>/<cacheWrite> models <list>` summed over `<folder>/*.run.json`. A file that is not a valid bug file prints `<file name> invalid` (dev mode adds why) and the exit is 1. Sealed mode prints no string a bug file's writer chose outside its shape: a bug id must match `^ho-\d+$` (else the file is invalid), a file not named `ho-<n>.json` that is invalid (a run record too) is only counted (`invalid <n>`), a `source` outside catalog/extension, `kind` outside UI/logic/validation/data/other, `severity` outside high/medium/low and a model not named `claude-<a-z0-9->` count as `other-value`, and a `finished` that is not a boolean prints `finished: invalid`. Each write goes to a temp file in the folder that is then renamed over the bug file.

`oracle pairs` lists the candidate source pairs `(commit, owner task)` of the task repo (step 5, ruling 7) into `sources/pairs.tsv` (`commit task kind hunks`): `later` = a commit of a `tasks/<task>.tsv` row with `tests_changed` `yes` and a hunk whose owner (`hunkOwners` over every task's rows, ties to the earlier task of `tasks.json`) is a kept task, with those hunks; `in-task` = a commit of `git rev-list --first-parent <base>..<end>` of a kept task that changes a file `isTestPath` accepts, with every non-test hunk of `git diff -U0 --no-renames <c>^ <c>`. `hunks` is `file:old` (the hunk's first old line) joined by `,`, empty for a commit that changes tests only. `--drop` leaves tasks out (their hunks still count for ownership). It prints `<task>: in-task <n>, later <n>` per kept task.

`oracle label` runs labeller `<1|2>` (`sealed-agent`, tools `Read,Grep,Glob,Bash`, `--settings briefs/label-settings.json`) on one task's pairs. Its prompt `sources/prompts/label-<task>.md` (the same for both labellers) is `briefs/label.md`, the task's plan and range, and per pair the commit, kind, subject and owned hunks. The reply must hold a JSON array `[{ commit, label }]` naming every pair once, `label` `fix|requirement change` (later) or `fix|build` (in-task). Each run's record gets `shown`: how many distinct listed commits it named in a Bash `git -C <repo> show` call whose tool result is not an error (the reading gate). A run whose reply does not label every pair, or whose `shown` is below the distinct commits listed (a record with no `shown` counts as below), is rerun once as `label-<r>-<task>-2`, whatever its labels; the rerun counts even when it reads too little again. A run with a `.run.json` is never repeated. It prints only `label <r> <task>: pairs <n>, labelled <n>, runs <n>, read <shown|unknown>/<commits>`, never the reply.

`oracle labels` merges into `sources/labels.tsv` (`commit task kind l1 l2 source`): each labeller's label comes from the rerun's reply when it ran, else the first; a pair that reply does not label validly (or names twice) reads `none`. `source` is `none` when either label is `none` (unlabelled, not a disagreement), `yes` when both say `fix`, `no` when both give a label other than `fix`, else `step9`. It prints `pairs, agreed fix, agreed not fix, disputed, unlabelled` per task, per kind (`later`, `in-task`) and in total, then `source commits: <n>` (distinct commits of the `yes` pairs), and exits 1 while any pair is unlabelled.

`oracle write` runs one sealed writer (ruling 9 of step 5; `sealed-agent`, tools `Read,Glob,Grep,Write,Edit`, a `--settings` file that grants `Read` and `Edit` under its output folder only, as `additionalDirectories`, by the path given and by its real path when a symlink lies on it, since the agent's `Write` resolves the real path; controller ruling) and moves its checks into oracles. The prompt file is written only when a writer runs, and the tool adds `promptSha` (sha256 of the prompt) to its run record. A writer whose run record exists is not run again: `write` then only judges and moves its output again, so a rerun is idempotent (delete the record to rewrite); when the prompt it would build today differs from the record's `promptSha` (or the record has none), it prints `write <x>: refused 1 writer run whose prompt differs from the one it ran with`, moves nothing and exits 1. A run that leaves no manifest, an empty one, or only `interface: none` entries is run once more as `-2` (controller ruling: the same prompt with its output folder named `<dir>-2`, its own output folder `<dir>-2`, reply `<name>-2.reply.md` and settings `<name>-2.json`; the first record stays) and the second run stands whatever it holds; the counts then add `rerun: the first run left no entry or only interface none; the second run stands`. The writer leaves `manifest.json` (`[{ id, hunk, origin, behaviour, interface, severity, file? }]`) and its check files in its output folder. An entry is refused, by the first reason that holds: `id` (not `<sha7>-T<n>` with the fix commit's sha7), `duplicate id` (every entry of that id), `fields` (`origin` or `behaviour` empty), `severity` (not `high|medium|low`), `interface` (not `browser|http|api|window|files|cli|library|none`; for a source commit not one of the rules' `kinds`), `hunk` (no agreed pair owns it, or not a source hunk of the PR), `file` (an entry other than `interface: none` has no file: for a source commit `<id><suffix>` exactly, else the one named `<id>.*`, or for an external entry the `file` it names), `import` (source commit: its file names a module, by `from '…'`, `require('…')` or `import '…'`/`import('…')`, outside the rules' `imports`, or loads one by a computed `require(…)`/`import(…)`), `leak` (its file holds 8 or more characters of the fix commit's hash, or the file path of any `origin`, written `<test file>::<test name>`; the sha7 alone is the id prefix, which a runner that cannot put a hyphen in a name writes in other forms such as `<sha7>_T1`). Each written entry is `{ id, fix_commit, task, hunk, origin, behaviour, interface, severity }` (+ `file` for an external one); `fix_commit` and `task` are set by the tool. It prints `write <sha7|task>: writer ran|reused code <c>, entries <n>, written <w>, refused <r>`, `refused: <reason> <n>, ...`, `per task: <task> <n>, ...`, `interface none: <n>`, `severity: high <n>, medium <n>, low <n>` (counts only), and exits 1 when the writer left no manifest. Since the `-2` rerun's prompt names its own folder (controller ruling of step 6), the step 5 `-2` writer records hash stale: `write` run again on those commits or tasks prints the stale-prompt refusal line.

- A source commit (`<task.json>` = the task repo's task file): the pairs of `sources/labels.tsv` with `source` `yes` give the hunks in scope (`sources/pairs.tsv`), each with its owner: an in-task pair's task, except a hunk a later pair lists, which keeps that pair's task; an in-task pair with no source hunk puts hunk `none` in scope for its task. The check rules are data, `briefs/oracle-re.json` (`{ suffix, imports, kinds }`: the check file's name after the id, the module specifiers a check may import, the interface kinds). The writer runs at the commit (`--at`); its prompt `re-work/prompts/<sha7>.md` is `briefs/oracle-re.md`, the id prefix, the hunks with their owners, `git show -U0` of the hunks' files, `git show` of the commit's test files (`isTestPath`), every top-level file of `oracle-scaffold/` and the output folder `re-work/<sha7>/`. Each accepted check file is copied into `<owner>/oracle/` and its entry added to that `manifest.json`, after this commit's earlier checks (ids `<sha7>-T*`) leave the oracle of every task with an agreed pair; a receiving oracle gets the scaffold's top-level files and a `node_modules` symlink to the scaffold's. The moves of parallel writes are serialized by the lock folder `re-work/.lock`.
- An external task (`<task>` of `ext/sample.tsv`): skipped with `<task> skipped no serve recipe` unless the task's last line in `ext/step5-logs/serve.tsv` (the serve driver's verdicts) is `servable` and `ext/serve/<key>/serve.json` exists. The writer runs on `ext/env/<key>.json` at the end; its prompt `<task>/work/write.prompt.md` is `ext/briefs/oracle.md`, the id prefix (sha7 of the end), the PR's source hunks (`git diff -U0 base end` outside its test files), its test files (`pr.json` paths matching the stack's `testPaths`), the fail-to-pass ids (`f2p.json`), the task recipe's Dockerfile and test command, the serve recipe without `briefSha`, the PR's diff and the output folder `<task>/work/write/`. `runner.json` must parse as `oracle-run` reads it, its `layer` must hold only `RUN` lines (a line after one ending in `\` continues it) and it must not leak; otherwise `write <task>: ... runner.json missing or invalid`, exit 1, and no oracle is written. Then `<task>/oracle/` is replaced by the output folder's files without the manifest, a leaking file, or a file only refused entries use, plus the accepted entries' manifest.
- `--batch 2` (step 9 ruling 7), a source commit of the task repo: the pairs of `step9/batch2.tsv` (`commit task kind`, the pairs the human answered `fix`; `human apply labels` writes it) with that commit (compared by sha7) give the hunks in scope, owners as above; a commit no row names prints `write <sha7>-b2 refused: no pair of step9/batch2.tsv names it`, exit 1. The prompt is the one above with only those hunks and the line ``The ids start at `<sha7>-T<k+1>`.``, `k` = `highestOf` (the highest number of the prefix in every `<data>/*/oracle/`, `*/step/oracle/` and `*/seeded/oracle/` manifest, dropped entries too) when the writer first runs; the run record keeps that first id (`ids`), so a rerun gives the same prompt. Folder `re-work/<sha7>-b2/`, prompt `re-work/prompts/<sha7>-b2.md`, reply `re-work/<sha7>-b2.reply.md`, settings `re-work/settings/<sha7>-b2.json`, label `write-<sha7>-b2` (the `-2` rerun and `promptSha` rules as above). An entry with an id at or below `k` is refused `id`. The move removes nothing: each accepted entry is appended to its owner's `oracle/manifest.json` (with `batch: 2`) and its file copied in, an id the manifest already holds (a rerun) is not added again, and the scaffold is copied only into an oracle that had no manifest; every earlier entry and file stays byte for byte. The count lines name `<sha7>-b2`.

`oracle validate` validates one task's checks (rulings 10, 11 and 13 of step 5). Pass 1: for a task of `tasks.json`, one `grade <task.json> <task>/oracle --validate <fix> --bad <fix>^ [--bad <task end>] --base <task base> --sealed --reuse` per distinct `fix_commit` of its checks (manifest entries not `dropped`, interface not `none`), `--bad <task end>` only when the fix is not an ancestor of the end (`merge-base --is-ancestor`); when the task file names an `appFile` and the base commit lacks it (controller ruling: no app at the base, so nothing the task builds exists there), `--base` is left out and every check's base result is set to `precondition` and its verdict taken again with it, the file and each check marked `stage: "no app at base"` (printed `validation-<ref7> (no app at base): <id>=<verdict> ...`); any other base that fails setup stays `error`; for an external task, one `grade env/<task>.json <task>/oracle --validate <end> --bad <base> --sealed --reuse` (no `--base`), and the removal `ext remove` makes of what `<task>/docker.json` records after each pass. After such a grade, when the last line of `<task>/build/readiness.tsv` for the end or the base and this oracle is `not ready` or `timeout` (that run's JUnit was the empty one), every check of the validation becomes `{ verdict: "error", stage: "not ready at <sha7>" }` (the file's `stage` too; printed `validation-<ref7> (not ready at <sha7>): error <n>`) and that commit's `grades/<sha7>.json` is deleted, so the next pass runs it again instead of reusing it; grade and `verdict` themselves are unchanged (a product that does not serve still scores 0 in steps 7 and 8). `grade` runs in process; one that throws or exits non-zero writes `validation-<ref7>.json` with `{ id, verdict: "error", stage }` for that ref's checks (`stage` the first line of grade's message), prints `validation-<ref7>: error <n> (<stage>)`, and the task goes on; `error` is unscored (`unscored`). Then at most two fixer rounds, each over every `broken` check of the task (ruling 11): one sealed fixer per ref (`fix-<round>-<task>-<ref7>`, `--at <ref>`, tools `Read,Glob,Grep,Write,Edit`, settings granting `Read` and `Edit` under `<task>/work/fix-<round>/<ref7>/`, a copy of the oracle without `node_modules`, and `Read` under `<task>/logs/`), its prompt `briefs/fix.md`, the broken checks' manifest entries, the paths of the last sealed log of each of the ref's runs and the copy's path. Every file of the copy that differs from the oracle counts as `changed`; only a broken check's file (with every check that file holds) and, external, `runner.json` go to one sealed comparer per ref (`compare-<round>-<task>-<ref7>`, `--tools Read`, no commit; its prompt `briefs/compare.md` and each such file before and after, inline), whose reply holds `[{ id, verdict: "same"|"changed" }]`; a file is copied into the oracle (`kept`) only when the reply calls every check it holds `same` exactly once (else `comparer changed`) and it passes the writer's gates (`gateFails`, else `gate refused`): no `leak` (8 or more characters of the fix commit's hash, or the path of an origin of that commit's checks), for a task-repo check no module outside `briefs/oracle-re.json` `imports` (nor a computed one), for an external `runner.json` a file `parseRunner` reads with a RUN-only layer; a changed file outside that scope (or deleted) is discarded unread (`out of scope`). Each round with a kept change is followed by a pass over the refs it changed (a round that keeps nothing leaves the oracle as it was, so no pass), so at most three passes. Prompts and records follow `write`'s rule (`promptSha`; a record is reused, a changed prompt refused). It prints `<task>: checks <n>, valid, weak, broken, error, pre-existing, absent-at-base <n each>, interface none <n>, fixer rounds <r>, changed <c>, kept <k>, comparer changed <n>, gate refused <n>, out of scope <n>` (+ `pre-existing moved out <n> (<id> to <task>, ...)` from `moves.json`). An external task with no `valid` or `absent-at-base` check prints `<task> dropped no valid check` and appends `dropped` to `ext/walk.tsv`, except when some check is `error`: then `<task> not judged: <n> checks error`, and nothing is appended.

`oracle validate <task.json> <task> --ids <id,...>` (step 9 ruling 7; a task of tasks.json only) validates only those checks (an id that is not a check of the oracle, dropped ones included, throws, exit 2). It puts them in a temporary oracle `<task>/work/ids-b2/oracle/` (a folder per call tag: `ids-b2` for this command, `ids-split-b2` for split's call, so a later call never overwrites an earlier call's grade records; a pre-step-9-fix `<task>/work/ids/` is left as it is) (the scaffold and their check files, their manifest entries; rebuilt each call, as `sweep/oracle/`), so `grade` writes its grades, logs and `validation-<fix7>.json` under `<task>/work/ids-b2/`, and runs the validation above on it: per fix commit the same `--validate <fix> --bad … [--base …] --sealed --reuse`, then at most 2 fixer rounds over the broken ones among them, in `<task>/work/fix-b2-<round>/` (labels `fix-b2-<round>-<task>-<sha7>`, `compare-b2-…`; the fixer's copy holds only these checks; the writer's leak gate takes the origins of the whole oracle). It prints the validation line over these checks only. Their verdicts are then merged into `<task>/validation-<fix7>.json`: an id's entry is replaced in place or appended, every other entry and field stays (a file that was not there is the temporary one). A kept fix is copied into the oracle; no other file changes. `sweep` is not run by it.

`oracle sweep` (ruling 12) puts every check of the kept tasks (`--drop` leaves tasks out, as for `pairs`) whose verdict is `pre-existing` into `sweep/oracle/` (the scaffold, the check files, their manifest entries), runs `grade <task.json> sweep/oracle --at <c> --sealed --reuse` once per distinct base and end of `tasks.json`, newest first (a grade that throws leaves that commit's results `error`; a commit without the task file's `appFile` is not run and reads `precondition` for every check, printed `sweep <c>: no app, every check precondition`), and gives each check `introducer` over the boundaries of the tasks before its owner. A receiver that is not dropped gets the check file and its manifest entry (`task` set to it; the scaffold copied in when missing) and the owner loses them; otherwise the check stays, recorded. Each owner's `moves.json` holds `[{ id, to, moved }]`. It prints `<id> moved to <task>` or `<id> recorded <task|none>`, `sweep: pre-existing <n>, boundaries <n>, moved <n>, recorded <n>`, then validates each receiver again for the moved checks' fix commits only, with no fixer round.

`oracle sheet` writes an external task's interface sheet (ruling 14 of step 5): one sealed agent (`sealed-agent ext/env/<key>.json sheet-<task>`, `--at` the end, tools `Read,Glob,Grep`, no settings) whose prompt `<task>/work/interface.prompt.md` is `ext/briefs/interface.md` and the task's `input.md` in a fence; the prompt gives no part of the PR's diff, no test path or id and no oracle (the agent can read every file at the end, the PR's tests too; the brief tells it to open no test, spec or fixture file). The reply `<task>/interface.reply.md` becomes the sheet from its `# Interface sheet` line on (a preamble is dropped). A `##` heading `bench/input-check.mjs` flags is replaced by `## Unnamed section <n>` (`n` its position among the reply's `##` headings) and its bullets are judged like any other. `deleted` counts the lines removed because input-check flags them, because a bullet does not parse as `- <kind>: "<name>"` with `<kind>` one of the brief's 23 kinds, or because they are any other text. `notfound` counts the parsed names that are not verbatim in a non-test file at the end: `git grep -F -l` of the name in the bare clone at the end commit must list a file that is neither `isTestPath` nor matched by the stack's `testPaths` (`ext/groups.json`), so a name found only in a test file is removed. A section left with no bullet is dropped. The sheet, which then passes `check()`, is `<task>/interface.md`. A reply with no title line, or with no name left after both removals, is a failed run and is run once more as `sheet-<task>-2` (`interface-2.reply.md`); a second failure prints `<task> sheet failed` and exits 1. The tool adds `promptSha` to each run record; a run whose record exists is never repeated (the sheet is rebuilt from its reply), and one whose `promptSha` differs from today's prompt prints `<task> sheet refused a run whose prompt differs from the one it ran with`, exit 1. Its only stdout line is `<task> sheet names=<bullets kept> deleted=<lines deleted> notfound=<names not found> input-check=PASS`.

`oracle classify` classifies a task's scored checks twice (ruling 15 of step 5, prereg 6.3). It refuses (exit 1, `<task> classify refused: <why>`) a task with no `input.md`, `interface.md` or oracle manifest, with no scored check, or with a scored check whose file is missing. A run record gets `promptSha` and is reused; when any record was made with another prompt, nothing runs, the folder and the prompt file stay as they were, and it prints `<task> classify refused a run whose prompt differs from the one it ran with`, exit 1. The folder, prompt and settings are written only when a rater is about to run. Its only stdout line: `<task> classified=<n> build=<b> requirement=<r> partly=<p> disputed=<d> kappa=<k> raw=<a> ac1=<c>` (two decimals, `none` when no check has two labels).

An original an earlier pass restored is put back as split: its new checks are un-dropped, its `requirement` label is removed, and the split's files go back into the oracle from the split's `out/` (for a shared file, the latest split of that file). Its new checks are then validated and fixed like the others.
2. `validate` runs on the task with the originals' fix commits as refs (an external task has one ref), then at most 2 fixer rounds over the new checks that are `broken` (ruling 11, with comparer and gates as in `validate`). Their folders and labels are their own: `work/fix-split-<round>/`, `fix-split-<round>-<task>-<ref7>`, `compare-split-<round>-...`. So a fixer record of `validate`'s own rounds never makes them stale. A throw or a non-zero exit prints `<task> split validate failed (<first line>); the new checks are not classified`, exit 1, and a rerun validates again.
3. An original with a new check that has no verdict or is `error` is not judged: it is neither restored nor decided, and the next run validates it again.
4. 6.3 (controller ruling): a judged split none of whose new checks is `valid` or `absent-at-base` did not split the check. The original loses `dropped` and `split_into`, gets `restored_from_split` (its new ids) and gets `requirement` in `labels.json`. Its new checks get `dropped: true` and `drop_reason: "split gave no scored half"`. A shared file (a grouped original's `file`, which the splitter rewrote) can only go back whole, so such a split is not restored (and not decided) while a split of the same file stays; that prints `<task> split restore blocked for <n>: ...`. A judged split with a scored half stands.
5. Settling, for every restored original whose split files are still in the oracle (`settled=<n>`): the new checks' own files are removed from the oracle, and a shared file is put back from the `in/` of its first split, as it was before any split. Then `validate` runs again on those originals' fix commits, without fixer rounds, so each original gets its own verdict in the oracle as it now is (`grade --validate` writes only the checks that are not dropped).
6. A judged original goes into `splitDone` (a restored one only once its own verdict is not missing or `error`) and is never split or passed again.

The scored new checks of the splits that stand are classified as above, each round taking only the ones no earlier round had: `work/classify-split/` (`classify-split-<r>.*`) first, then `classify-split2`, and so on. The originals of a `classify-b2*` round (step 9 ruling 7) differ in two ways: their new checks (and a restored original's settling) are validated through `validate --ids` with tag `split-b2-` (`work/fix-split-b2-<round>/`), so no other check of the fix commit is graded again, and they are classified in rounds of their own, `classify-split-b2`, then `classify-split-b2-n2`, …, whose disputes `human build classify-2` takes. Agreed `traceable` is `build`, agreed `not traceable` or `partly` is `requirement`, disputed stays unlabelled. `agreement.json` `splitRounds` holds each round's `name`, `ids`, agreement and lists (`split` is the first; an older file's `split` without ids takes them from its raters' labels and disputed list). Before its last line it may print `<task> split restore blocked for <n>: a shared file holds a split that stays`, the lines of each `validate` it runs (with grade's lines), and on a failure `<task> split validate failed (<first line of the error>); the new checks are not classified` (exit 1) or the classifier's refusal. Its last line: `<task> split partly=<n> split=<s> failed=<f> restored=<r> settled=<t> stale=<k> new=<new checks of the splits that stand> classified=<n> build=<b> requirement=<r> disputed=<d>`; exit 1 when a run was made with another prompt.

Then at most two fixer rounds over the `broken` checks, as `validate` runs them (`fix-step-<r>-<task>-<end7>` and `compare-step-<r>-<task>-<end7>`, in `step/work/fix-step-<r>/`; a fixer's manifest entries carry no `step`). (5) `<task>/step/labels.json` labels every scored step check (`valid` or `absent-at-base`) `build`, and `<task>/step.json` is `{ oracle: "step/oracle", ids, candidates, seed }`: the scored ids in pick order and the count of resolved entries. A lister or writer whose record holds another prompt prints `<task> step refused a run whose prompt differs from the one it ran with`, exit 1. Its last stdout line is `<task> step listed=<n> resolved=<r> picked=<p> written=<w> refused=<f> none=<x> valid=<v> absent-at-base=<a> weak=<k> broken=<b> error=<e> fixer rounds=<r> ids=<i>` (`written` counts accepted entries, `interface: none` ones too; `fixer rounds` counts the rounds run in that invocation, so a rerun can print another number); only grade's own lines and a validation's `error` or a fixer's refusal line come before it. A rerun after a round that kept a fix may print a fixer's stale-prompt refusal line (the fixer's prompt now holds the fixed check), and the data files (`step.json`, `labels.json`, the step oracle) stay unchanged. A lister entry whose `title` holds a line break is not a valid entry, since `git grep -e` would read its lines as separate patterns joined by OR. A fixer's folder copy holds the manifest without `step`.

`proxy serve` (`bench/proxy.mjs`; step 11) is the HTTP proxy between an arm box and the API. It reads `BENCH_PROXY_TOKEN` (required; exit 2 without it), `BENCH_PROXY_AUTH` (`authorization`, sent as `Bearer <token>`, or `x-api-key`), `BENCH_PROXY_BETAS` (comma-joined, appended to the request's `anthropic-beta`), `BENCH_PROXY_PORT`, `BENCH_PROXY_UPSTREAM` and `BENCH_PROXY_COUNTS` (default `/out/proxy-counts.txt`). It forwards only `POST /v1/messages` and `POST /v1/messages/count_tokens` (a query string is kept), drops the box's own `authorization` and `x-api-key`, streams the answer back, and answers 403 `permission_error` for another path, a body that is not a JSON object, a `tools` that is not an array of objects whose `type` is absent or `custom`, `mcp_servers`, `container` or any `source` of type `url` at any depth (reasons `path`, `body`, `tool`, `mcp`, `container`, `source`). It forwards the JSON it judged, not the raw bytes, and sets no idle or fetch timeout on an allowed request. `BENCH_PROXY_AUTH` is only `authorization` or `x-api-key` (exit 2 otherwise). An internal error answers a fixed 500. It rewrites the counts file on every request as `allowed <a> refused <r>` plus ` <reason>=<n>` per reason, sorted (an upstream failure is a 502 counted as `upstream=<n>`, not a refusal), and writes nothing else anywhere.

`oracle seed` makes a task's seeded bugs (rulings 2-9 and 12 of step 7): `seed <task>` for an external task (5 candidates, keep 3), `seed <task.json> <task>` for a task of `tasks.json` (2, keep 1); each stage reuses its record. (1) `seedRepo`, then one sealed seeder (`sealed-agent env/seeded/<task file> seed-<task>`, `--at` the end, tools `Read,Glob,Grep,Write,Edit`, granted only `<task>/seeded/work/seed/`). Its prompt is `ext/briefs/seed.md` or `briefs/seed-re.md`, the oracle writer's brief, the fenced `input.md`, the changed ranges of `diff -U0 --no-renames <base> <end>` (test paths left out), the count and ids, the mechanics (external: the task and serve recipes; else: the scaffold) and the folder; never the interface sheet, an oracle, labels, `ext/sealed/` or the PR's text. Ids are `<end7>-T<n>` after `highestOf`, kept in its run record (`ids`). (2) `judge` and, external, `runner.json` (`<task> seed runner.json missing or invalid`, exit 1), then a candidate is refused with one word: `judge`'s, or `id` (not given), `fields` (no `edit` strings or `description`), `origin` (not `<edit.file>::<edge>`), `interface` (`none`), a `seedCommit` gate, or `duplicate` (the commit an earlier candidate gave: one commit is one bug; its ref is deleted). Each other candidate is a commit `refs/seeded/sb-<task>-<k>` in the sealed repo (`k` in id order); accepted checks go to `seeded/oracle/` when the seeder ran or none is there yet, so a rerun keeps a fixer's work. (3) `grade <seeded env> seeded/oracle --at <end> --sealed --reuse`: one that throws, exits non-zero, has no JUnit, or whose readiness line says not ready prints `<task> seed not judged`, exits 1 and drops nothing (a not-ready grade file is removed, so a rerun runs it). (4) At most 2 `fixRound`s (`work/fix-seeded-<r>/`) over the checks that did not pass at the end, each kept fix followed by a grade at the end; an end with every check still `error` is not judged the same way, its grade file removed. (5) Over `queuePick` of the bugs that pass at the end, `grade --at <bug>` and `ownVerdict` on the bug's own check, until the count is `valid`; a bug with no results is `error`, with its `stage` in the validation (a never-ready bug's grade file is removed, so a rerun runs it), and a verdict gets no fixer. It writes `seeded/validation-<end7>.json` (so `grade` excludes all but the kept checks: a check that failed at the end is `broken`, an ungraded spare `error` with stage `not graded`) and `seeded/bugs.json`. It prints `grade`'s own `<sha7> junit=...` lines and then only `<task> seed candidates=<c> refused=<r> pass-at-end=<p> fixer=<rounds of this run> graded=<g> valid=<v> weak=<w> broken=<b> error=<e> kept=<k>`, where `broken` counts the checks that failed at the end too. An external task's images are removed after stages 3-5, whatever the outcome. Beyond `<task>/seeded/`, `seeded/repos/` and `env/seeded/`, a real run also adds to `<task>/build/`, `<task>/docker.json` and `ext/sealed/<slug>/logs/`.

`oracle kills` (`kills <task>`, `kills <task.json> <task>`; ruling 10) measures the task's existing oracles at the kept bugs of `seeded/bugs.json`: `grade <seeded env> <task>/oracle --at <end> --sealed --reuse`, then `--at <bug>` per kept bug, and the same on `<task>/step/oracle` only when `step.json` has `oracle: "step/oracle"` and ids. The end is not graded when its grade still stands (same commit, `junit` ok, the folder's current oracleSha, not not-ready), since `grade` rewrites the file even on `--reuse` and the step 6 lock hashes it. That kept end grade can hold an older `excluded` list, so a kill leaves out the checks in the *bug* grade's `excluded` (rewritten from today's validations), and takes the results at the end from the end grade. An end or bug grade with no results (none, `junit` not ok, not ready, or every check `error`) prints `<task> kills not judged`, exits 1 and writes no `kills.json`, and a not-ready or all-`error` grade file is removed, so a rerun runs it; an `error` beside real results is simply no kill. It writes `seeded/kills.json` (`[{ id, fix: { killed, of }, step: { killed, of } | null }]`), and prints `grade`'s own lines and then only `<task> kills bugs=<b> fix=<killed bugs>/<b> step=<killed bugs>/<b>|none`. A real run also adds to `<task>/logs/` and `<task>/grades/`, and to `<task>/step/` for the step oracle.

`replay-summary` counts the verdicts in `<results dir>` per layer and bug set and prints markdown: n, caught, missed, error and the catch rate over caught + missed; `unit+int` (a bug caught by either; else error if either errored, else missed); the severity-weighted rate (high 3, medium 2, low 1; error runs and bugs without a severity left out, those bugs counted on an `unweighted bugs` line) for a set with severities; the summed `layer` + `judge` usage and models per agent layer (every run's tokens, an `.error1.json` too; the verdict is the good record's); a per-bug table. A `<id>-<layer>.out` that is empty or has no `<id> caught|missed|error` last line, a record that is not a verdict, and a bug whose only file is `.error1.*` count as `error`; a good rerun file wins over its `.error1.*`; `baseline-*.xml` and a bug in no given set (or `dropped`) are ignored. It prints ids, verdicts, severity-based aggregates, usage and model names (`claude-<a-z0-9->`, else `other-value`) only, never a description, quote, finding, fix, file or hunk, so it is safe on a sealed folder.

`stick hash` (step 10 ruling 5) writes one `<sha256>  <path>` line per regular file under `<data>` (the path relative to it, the bytes hashed, lines sorted bytewise by path) and prints `stick hash: files <n>, link <l>, node_modules <m>, store <o>, secret <s>, transcript <t>, rewritten <r>, special <x>`, then one `stick hash <top folder> <n>` line per top-level folder (files at the root of `<data>` count under `.`). It never stats or follows a symlink: each link is left out and counted under `link` (so `p8b` → `8b` is hashed once, as `8b/…`). Also left out and counted, a folder once and not entered: `node_modules` folders; inside each git store (every folder directly under `ext/repos/` or `seeded/repos/`) every entry but `HEAD`, `config`, `shallow`, `packed-refs`, `refs/**` and `objects/info/alternates` (`store`: the objects, `FETCH_HEAD`, `index`, `logs/`, `hooks/`, `info/`, `description`); the secrets `arm/box.env` and `step9/pages/*.token`; the run transcripts `results/*/*.jsonl` (`transcripts/` is hashed); and the files every grade or removal rewrites, `*/docker.json`, `*/build/readiness.tsv` and `ext/removed.txt` (`rewritten`; `*` is one path segment); a socket, FIFO or device is neither opened nor hashed and counts under `special`. `stick hash` exits 2, printing `stick hash: --out is inside the data folder` and writing nothing, when `<file>` (links of the file or of its parent folder resolved) is inside `<data>`. `stick compare` (ruling 6) reads every `^[0-9a-f]{64}  <path>$` line of a lock or a manifest, the last line of a path superseding earlier ones (counts are of paths); a `progress/` path is read in this repo, any other under `<data>` (through links, so an earlier lock's `p8b/…` still resolves). It prints `stick compare <file>: hashed=<n> equal=<e> changed=<c> missing=<m> unexplained=<u>`, then `changed <path> <reason>` and `missing <path> <reason>`, the reason that of the first glob of `--reasons` (`<glob>\t<reason>` lines, no header, `Bun.Glob`) the path matches, else `unexplained`; with `--reasons`, one `reason <glob> changed=<c> equal=<e>` line per glob, counting every compared path that glob matches (per glob, not first match), so a predicted change that did not happen shows. It exits 1 when any path is missing (even one with a reason) or unexplained.

## The arm box (`bench/box.mjs`)

`enterBox` is the only way in for an arm agent; a failure on the way in removes what it made and throws, and no turn runs. In order: the disk floor; `bench-arm/fw:1` (`alpine:3.22` plus iptables and python3, built if missing or without python3, the one name outside `docker.json`); the task's serve image at the base and the arm layer `FROM` it (`ARM_LAYER`: takes the bench files and any `.git` out of `/work`, installs git when the image has none), both recorded before each build; `API_HOSTS` resolved to IPv4 (a name with none throws); `docker create` from `boxArgs` (no mount, no added capability, of Docker's defaults only CHOWN, DAC_OVERRIDE, FOWNER, KILL, SETUID and SETGID kept, 6 GB, `sleep` of `(RESUMES + 2) × turnTimeoutSec + 600` s, so a box ends by itself if the host process dies) and `docker start`; the rules set by the helper in the box's network namespace with `NET_ADMIN`, the box never has it; the check of ruling 3 from the same namespace, always by the real helper, so a rule step that did nothing fails it, with a throwaway listener on an ephemeral host port standing for the host, since no check connects to a real service there; only then `docker cp` of the CLI, the fresh `.git` (as a tar) and the empty settings, and the `env` commit of what the image build changed, so the agent starts on a clean tree.

It gives `{ envCommit, turn(opts) -> { out, code }, product(destFile), leave(), box: { name, image, memoryGB, ips, routes } }`. A turn is `docker exec` with `--env-file <data>/arm/box.env` of `timeout -k 30 <turnTimeoutSec> /arm/claude …`, stdout and stderr in files in the box, so a background server cannot hold a pipe; the stdout file is copied out and read only if it is a plain file. A missing `box.env` throws before any Docker call, and its content is never printed. `code` is the exit code, `'timeout'` for 124 or for a 137 at or past the limit, `'memory'` for a 137 before it, or `'killed'` when the host's limit (`turnTimeoutSec + 120`) passes or the box died or restarted (a restart has no rules, so `turn` and `product` compare `StartedAt` first); `killed` kills the box. A plugin dir is refused (the plan of step 11). `product` gives `{ code: 0 }` or `{ code: 'killed' }`: it kills everything in the box but PID 1, so nothing of the agent's can swap the bundle, commits with a plain `git add -A`, so ignored build outputs stay out, and copies out a `git bundle` of HEAD: the folder never comes back. `leave` is `removeRecorded`, and can be called twice; `bun bench/ext.mjs remove <task>` clears what a killed run left.

```sh
bun bench/box.mjs proof <task>                     # one line per row of step 8's boundary table, `<row> ok|FAILED`; exit 1 on any row that is not ok (FAILED or skipped); writes <data>/arm/proof-<task>.json
```

`proof` enters a box at the task's base and needs `<data>/arms.json`. With no `box.env` the two rows that need a real turn print `skipped: no box.env`. `blocked targets` runs each target and DNS from a plain container with no rules, where each must answer (a refusal is an answer), then under the rules, where each must be silent. `root cannot undo it` and `no vsock` run from a twin, root with the box's capabilities in the box's namespace from the helper image, so an image with no `ip` cannot pass by absence; each wants the kernel's refusal. `a real database is out of reach` wants the throwaway listener reachable with no rules, silent under them, and no `real_estate` string in the env.
