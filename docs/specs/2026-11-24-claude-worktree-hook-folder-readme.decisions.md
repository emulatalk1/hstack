## Design

The project's own rules for how code is written: none in a file of their own; `CLAUDE.md` and the `README.md` say what the scripts and hooks do, and the head of `scripts/hstack.ts` how it reads bytes.

`scripts/hstack.ts` stays one file, as every earlier spec kept it. Its hooks gain three pieces, each with one job, each the one home of its rule:

- `hookDir(input)`: the folder a hook judges (E2, E3). The rule "follow the `cwd` only into a work tree of the project's repository" lives here and nowhere else; the stop, prompt, start and worktree hooks all call it.
- Whose run it is: `meet(dir, id, judged)` writes `owner` (the first hook with an id that judges the work tree after `start`, when the run is not `stale`) or `came` (a hook of another session); `mineAt(dir, id)` says whether the run in a state folder is this session's (not `stale`, and the owner is the id, or the input has no id). These two hold the rule of behaviour 33/34 and of E1, E14; `takeup` reads `came` and writes `owner` (E9, E10).
- The runs of the repository: `worktrees()` lists each work tree with its folder and its state folder (read from git, with no `state()`, no `cd`, no write), and `runOf(dir)` reads one state folder (waiting, unfinished, stale, owner, spec, the steps not recorded). `elsewhere(id)` is the one search for an unfinished run of this session in another work tree. They feed the stop hook, the worktree hook, the start text, the resume and `runs`.
- `missing()` and `recorded()` take the state folder as an argument (defaulting to `S`), so that they read another work tree's run.
- The stop hook: one `hold(dir, why)` holds a turn and keeps the count of the run's own state folder (E6); every place that let a turn end because nothing in its folder was this session's goes through `endOrElsewhere()`, which holds for a run of this session in another work tree, naming its folder, and otherwise ends. The branch words come from `branchWords(dir, top)`, the one home of behaviour 30's rule.
- The worktree hook `hook-worktree`: records the coming (judged folder, and the work tree of `tool_input.path`), then refuses when this session's run is unfinished here or `elsewhere`, and prints nothing otherwise; it never fails (a try around it, exit 0), as the prompt hook.
- `start`/`takeup` write `branch`; the files of a run move with it in `moveRun()` (E15).

Corrections made while building and after review round 1 (the lines above stand as first written):

- There is no `runOf(dir)`: `waiting(dir)`, `unfinished(dir)`, `missing(dir)` and `recorded(step, dir)` read a state folder, and each caller uses them. There is no `branchWords(dir, top)`: behaviour 30's rule lives in `runWhy(dir, top)`, inside the stop hook, which writes the whole reason of a hold for a run of this session, branch words included (review round 1, design finding 2).
- The rule of whose run it is has one home, `ownedBy(dir, id)` (the owner is the id, and the run is not `stale`); `mineAt(dir, id)` adds the case of a hook with no id; `ownElsewhere(id, here, trees)` is the one search over the other work trees, and `elsewhere` its first line. The stop hook, the worktree hook, the resume and the start text call these (review round 1, design finding 1).
- The hand-over of a run to the session that came has one home, `handOver()`, called by `approve` and by `takeup` (review round 1, finding 1).
- `meet` also removes `came` when the owner's own hook judges the work tree again, and the worktree hook records a coming only for a call it lets run (review round 1, finding 2).
- `meet` removes `came` whenever the owner's own hook judges the work tree, whether the run is `stale` or not: the owner who judged it last is the last to come (review round 2, finding 1).
- The start hook with `clear` hands the run of its work tree to the new id (E20), before `meet`, which would otherwise write the new id to `came`.

The texts: the playbook is the one home of the loop's rules (the worktree, the base, the merge, no move during a run, the time); the four agents' files repeat the rule of three ways and their own "done", because an agent runs apart with its own file only. The README's status paragraph and `CLAUDE.md` describe the four hooks; the README names `/hstack:build` in the opening paragraph and the quick start. The rename is `git mv skills/build-implement skills/implement` with the two lines of `SKILL.md` changed.
