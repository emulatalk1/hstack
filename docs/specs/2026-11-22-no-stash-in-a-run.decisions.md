# Decisions of the builder: spec 5, no stash in a run

## Entry points

- `hstack.ts start` (`scripts/hstack.ts`, `case 'start'`): writes the state file `stash-base`, the entries the stash of the code repository holds, one line each, `<commit> <message>`.
- `hstack.ts gate` (`case 'gate'`): prints the `STASH ADDED: ` and `STASH GONE: ` lines after its lines on the oracle's files and on the tests; its exit code is not changed by them.
- `hstack.ts done` (`case 'done'`): prints the same lines before `done at <HEAD>`.
- `skills/build-implement/SKILL.md`, item 4: the text a builder reads at step 4.
- `skills/build-implement/tdd.md`, the item "A test that passes at once on this run's own code": the test rules of step 4.
- `skills/build/SKILL.md`: the rule "Git, in the code repository"; step 5 "Gate"; step 10, the items "The log" and the one with `$H done`.
- No new verb, no change to the usage lines, to `hook-start`, `hook-stop`, `fingerprint`, `entries`, `porcelain` or to `moveRun`'s list of what stays: `stash-base` is a file of the run and moves to `old/` with it, as `base` and `phases` do.

## Edges

- E1. How an entry is known to be the same one (left to the builder by the spec; the oracle's open edge "two entries with the same message"): by its commit, not by its message or its place. Two entries with one message are two entries; an entry popped and stashed again is a new commit, so it gets one `STASH GONE` and one `STASH ADDED` line. The codebase knows a file the same way, by its hash (`lock`, `gate`, `records-check`). Test: tests/no-stash-edges.test.ts "E1: an entry is known by its commit: of two entries with the same message, the one added after start gets its line, and the one held at start gets none"
- E2. What a `STASH` line holds besides its first words and the message (left to the builder): the entry's commit, whole, in brackets at the end: `STASH ADDED: <message> (<commit>)`. With it the user can look at an entry that is gone while git still keeps its commit (`git show <commit>`), and can tell two entries with one message apart. Test: tests/no-stash-edges.test.ts "E2: a STASH line ends with the entry's commit in brackets, which names a commit git still has after the entry is gone"
- E3. A run whose `start` recorded no stash (a run started by an earlier version; left to the builder): nothing can be compared. `gate` says so in one line, `stash: not recorded at start, not compared`, the way it already says `tests: no test-paths recorded, pre-existing tests not checked`; `done` prints nothing about the stash, as it prints nothing but its result today. No line starts with `STASH`. An empty stash at `start` is a record, an empty one: it is not this case. Test: tests/no-stash-edges.test.ts "E3: a run whose start recorded no stash: gate says it was not compared and prints no STASH line, and done ends the run with none"
- E4. `start` while a spec waits for approval (the oracle's open edge): the existing code keeps that run and writes nothing (`case 'start'`, its first line); the record of the stash is that run's and stays as the first `start` wrote it. Test: tests/no-stash-edges.test.ts "E4: a start while a spec waits keeps the run and its record of the stash: an entry added before that second start still gets its line"
- E5. A `done` that refuses (steps not recorded, an uncommitted change, a record changed after the check; the oracle's open edge): it prints its refusal and no `STASH` line, as it prints nothing else today; the lines come with the `done` that ends the run, and `gate` shows them at any time. Test: tests/no-stash-edges.test.ts "E5: a done that refuses prints no STASH line; the done that then ends the run prints it"
- E6. The order of the lines (the oracle's open edge): in `gate` after the lines on the oracle's files and the tests, in `done` before `done at <HEAD>`; the `STASH ADDED` lines first, in the order `git stash list` gives (newest first), then the `STASH GONE` lines in the order the entries stood at `start`. No test: the spec names no order and nothing a user does depends on it; the oracle's tests compare the lines without order.
- E7. A stash that cannot be read (the oracle's open edge; `git stash list` fails, as it does when `refs/stash` names an object that is missing): at `gate` and `done` nothing is compared and no entry is called gone; `gate` says `stash: could not be read, not compared`, `done` prints nothing about it. At `start` no record is written, so that the run is the case E3. Following the script's rule that a state file it cannot trust never turns into a wrong claim (`record`: "a broken state file ends the snapshot, never the phase"). Test: tests/no-stash-edges.test.ts "E7: a stash that git cannot read is not compared: gate says so and calls no entry gone, and exits as it would"; tests/no-stash-edges.test.ts "E7: a stash that git cannot read at start is not recorded: an entry that was there all along is not called added later"
- E8. A message with bytes over 127 (a label in Vietnamese): the line holds it as written. Every string of the script is a byte string (`scripts/hstack.ts`, its first comment), and `git` and `put` pass bytes through. Test: tests/no-stash-edges.test.ts "E8: a label with letters outside ASCII stands in the line as it was written"
- E9. A message of more than one line: git writes an entry's message on one line (it joins the lines of a label with spaces), so one entry is one line of the record and of the output. No test: the base (git) decides it, and no input of the script can make a second line.
- E10. An empty stash at `start`, and one that stays as it was: the record is an empty file, and nothing is printed. Test: tests/no-stash-script.test.ts "9 (guard): with an empty stash at start and now, gate and done print no line that starts with STASH" (the oracle's)
