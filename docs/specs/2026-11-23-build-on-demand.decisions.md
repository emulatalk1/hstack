## Design

The project's written rules: `README.md` (section "Development": every script and test is TypeScript run with Bun; no new `.sh` or `.mjs` file; the run state lives in `~/.hstack/<checksum of the git dir>/`) and `CLAUDE.md` (the reference of the hooks and scripts). No coding-standards file.

- `scripts/hstack.ts` stays one file, as the codebase keeps every verb and hook in it; the change adds to it and splits nothing (the stop hook's tangle of decision and git calls is a known debt of the log, outside this change).
- The stop hook's decision, which turns are held, lives in one place: the branch chain of `hook-stop`. The new rule is: hold only a run of this session that is not `done` (whatever changed), and a spec of this session that waits while the repository changed. "Of this session" is the existing mark `stale` (written at `startup` beside a run, removed by `approve`, `spec --drop`, `start` and the new `takeup`). No new state for it.
- The playbook's absolute path is computed once from the script's own place (`import.meta.dir`/../skills/build/SKILL.md) in one constant, `PLAYBOOK`, used by the hold reason and by the start text.
- The time in which no session worked on a run: one new state file, `last-stop`, the time the stop hook last ran in that state folder. One helper, `idleOff()`, adds `now - last-stop` to `started`; `takeup` and `hook-start` with `resume` (a run approved, not done, not stale) call it. The clock's rule stays where `offClock` is.
- `takeup` is a verb of the script beside `approve`, in its style: it checks (approved, not done, `stale`), refuses when the base commit or the oracle's commit (`oracle-commit`, when the run wrote one) is not an ancestor of `HEAD`, prints the commits of `HEAD` after the run's last recorded step (`last-head`, written by `mark` at each recorded step and by `approve`; `base` when there is none) and, when there are some and no `--with-commits` is given, changes nothing and exits 2, so the agent asks the user; else it takes the run up: removes `stale`, takes the idle time off, resets `stop-blocks` and the session's reference.
- `start` refuses beside an approved run not finished, whether of this session (as today) or of an earlier one (new): the message names the two ways on (`takeup` for that run, a new worktree for new work). A run of 0.3.3 or earlier with no `spec` line is still moved aside, as today.
- The hooks judge the folder the session works in: the `cwd` of the hook's input when it has one, else `CLAUDE_PROJECT_DIR`, else `.`. One helper, `hookDir(input)`, for the three hooks.
- Texts: the start text is one string in `hook-start`, as today; the rule "the loop runs only when the user types `/hstack:build`" lives in the build skill's header (the flag) and is repeated in the start text and in the descriptions of the three step skills on purpose: each is read by the agent apart, and each says only that the user starts the loop with `/hstack:build`.
- The playbook (`skills/build/SKILL.md`) holds the new cases of step 1 in its item "Brainstorm" and "Start"; the merge in step 10's item on the last reply. The worktree is made by the session's own worktree tool (Claude Code's `EnterWorktree`), which moves the session; the loop never moves a session by `cd`.
- The version stays 0.4.6: tests of spec 2, 4 and 8 pin it, and the spec approved no change of them.
