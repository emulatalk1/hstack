# Decisions of the builder: Spec 1, the mock-up server

Where the original came from: the brainstorming skill of the plugin `superpowers` (https://github.com/obra/superpowers), version 7.0.2, commit 22f0b463e7a5, MIT licence, Copyright (c) 2025 Jesse Vincent; its files `skills/brainstorming/scripts/server.cjs`, `start-server.sh`, `stop-server.sh`, `helper.js`, `frame-template.html`. This file and `scripts/LICENSE-mockup` are the only places that say so (open point 9 of the spec).

How it is built (the user, in the grill: Bun's own server and WebSocket may be used): one script, `scripts/mockup.ts`, with the verbs `start`, `stop` and `serve`; the browser's script in `scripts/lib/mockup-helper.ts`, which the server turns into JavaScript with Bun's transpiler when it starts; the frame in `scripts/mockup-frame.html`, the original's with the title and the brand line changed.

## Entry points

- `bun scripts/mockup.ts start [--dir <folder>] [--host <host>] [--url-host <host>] [--idle-timeout-minutes <n>] [--open] [--foreground|--no-daemon] [--background|--daemon] [--allow-network]`
- `bun scripts/mockup.ts stop <session folder>`
- `bun scripts/mockup.ts serve [--brainstorm-server-id=<id>]`, with its settings in the environment (`BRAINSTORM_DIR`, `BRAINSTORM_HOST`, `BRAINSTORM_URL_HOST`, `BRAINSTORM_OWNER_PID`, `BRAINSTORM_PORT`, `BRAINSTORM_TOKEN`, `BRAINSTORM_IDLE_TIMEOUT_MS`, `BRAINSTORM_LIFECYCLE_CHECK_MS`, `BRAINSTORM_OPEN`, `BRAINSTORM_OPEN_CMD`, `BRAINSTORM_ALLOW_NETWORK`, and from `start` with `--dir`: `BRAINSTORM_PORT_FILE`, `BRAINSTORM_TOKEN_FILE`)
- HTTP: `GET /`, `GET /?key=<key>`, `GET /files/<name>`; a WebSocket on any path
- In the page: `toggleSelect(el)`, `window.selectedChoice`, `window.brainstorm.send(event)`, `window.brainstorm.choice(value, metadata)`, a click on an element with `data-choice`
- Files of a session: `content/*.html`; `state/server-info`, `server-stopped`, `server.pid`, `server.log`, `server-instance-id`, `events`; with `--dir`, `<folder>/.last-port` and `.last-token`
- `hstack.ts start` (the folder `mockups` of the state folder)
- The README: the section of `mockup`, a line of "Known limits"

## The page's script and its tests

Behaviours 35 to 37 have no test of the oracle (its report says why). The builder's tests run the script of a served page on a stand-in page: `tests/mockup-edges.test.ts`, the tests whose names start with `35:`, `36:` and `37:`. They were written before the script's code, one behaviour's group at a time (35, then 36, then 37), not one test at a time; each was seen to fail on the empty script. The edge tests (E-numbers) were written after the server's code, which the oracle's tests had asked for; each was proven by breaking the code it rests on, in a copy of the script or in place, and seeing it fail.
